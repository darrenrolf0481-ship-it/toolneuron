# ToolNeuron: notes for coding agents

ToolNeuron is a browser IDE: chat modes, a CodeMirror editor, JS/Python
sandboxes, a reviewer swarm, browser-side git with GitHub push/pull. It is
built for **one person on their own server** (see README "Who it is for").
The README covers features, setup and env vars; this file covers how to work
on the code without breaking it.

The `.grok/` folder, `scripts/grok-*`, `server/`, `startup.sh` and
`public/__grok/` come from the original Grok app-builder export. Grok's own
rules for that sandbox are archived in `.grok/AGENTS.grok.md`; they do
**not** apply here (no `/workspace`, no port 8080 preview, no Vercel deploy).

## Commands

```sh
npm run dev:vm      # dev server on 127.0.0.1:8095 (what the browser tests expect)
npm run typecheck   # tsc --noEmit
npm run lint        # eslint
npm test            # scripts tests + app unit tests (node --test, no browser)
npm run test:e2e    # Playwright browser tests; needs dev:vm running
npm run build       # production build
```

All five must pass before a change is done; CI (`.github/workflows/ci.yml`)
runs them on every push and pull request. To run a script under
`scripts/with-app-env.mjs` by hand, use `npm exec -- node scripts/...` so
`vite` is on the path.

- **New unit test file?** `test:app` in `package.json` lists the files
  explicitly. Add yours there or it never runs.
- **Browser tests** wait with `gotoApp` / `reloadApp` from `e2e/helpers.mjs`
  (they wait for `data-ready="true"` on the page root). Never use
  `waitUntil: "networkidle"`. Shared helpers go in `helpers.mjs`: importing
  one `*.e2e.mjs` from another registers its tests twice.
- Browser tests fake `/api/chat`, `/api/clone`, `/api/git/push` and
  `/api/git/fetch` with `page.route`, so they need no keys. Keep it that way.

## Where things live

| Path | What |
|---|---|
| `src/lib/crimson/store.ts` | zustand store: state type, files, modes, packs, reset |
| `store-git.ts`, `store-chat.ts`, `store-persist.ts` | Store slices: git/GitHub, chat/handoff/terminal AI, saving and export/import |
| `store-shared.ts` | Fresh workspace, `session` (generation counter, chat abort), `cancelWork()` |
| `git.ts` | All git logic, pure and tested: blobs, trees, index, commits, branches, `merge3`, push plans, pull snapshots |
| `git-store.ts` | Git history in IndexedDB (stores `blobs` and `meta`, one transaction) |
| `prompt.ts` | System prompts, budgets, history sent to the model (pure, tested) |
| `providers.server.ts`, `src/routes/api/chat.ts` | Providers from env; streaming chat with fallback |
| `access.server.ts` | Access key cookie, rate limits, cross-site check |
| `github.server.ts`, `src/routes/api/clone.ts`, `src/routes/api/git/*` | GitHub calls: allowlist, clone, push, fetch |
| `swarm/`, `vault/`, `skills/` | Swarm review, encrypted vault, skill cards |
| `src/components/crimson/` | UI |
| `reviews/` | Past reviews and plans; `reviews/2026-11-11/consensus.md` is the latest |

Files ending in `.server.ts` are server-only. Import them inside handlers
with `await import(...)`, never at the top of a file the browser also loads.
`src/routeTree.gen.ts` is generated by the dev server: don't edit it, and
don't `git stash` while the dev server runs (it rewrites the file and the
stash races it).

## Rules that must not break

**Secrets and access**
- API keys and `GITHUB_TOKEN` stay on the server. Never send them to the
  browser, log them, or commit them. `.env` is never committed.
- Every AI and GitHub endpoint checks the access cookie, the rate limit and
  the same-site check (`guardAiCall` for AI, `guardCloneCall` for GitHub).
  New endpoints must too.
- The token is only used for repos on `GITHUB_REPOS` (`repoAllowed`). Without
  that list it is never used.
- `X-Forwarded-For` is ignored unless `TRUST_PROXY=true`.
- The AI is only called when the user sends something. No background calls.

**Git and GitHub**
- Push is fast-forward only (`expectSha`). The one forced ref update replaces
  this app's own placeholder commit in a repo that was empty, after
  re-checking it.
- Every push commit names its tree parent, so files the browser never had
  (binary, too large) stay as they are on GitHub.
- Pull and merge refuse to overwrite untracked files, to put a file where a
  folder is (or the reverse), or to run with uncommitted changes.
- Only one GitHub operation runs at a time (`githubBusy`). A pull whose
  branch, head or remote changed while it ran applies nothing; a push records
  its result against the branches it was planned for (`markPushed`).
- `merge3` must keep matching `git merge-file`; adjacent-line edits conflict.

**Saving**
- The workspace is saved to localStorage key `crimson_os_v1`. Git history
  lives in IndexedDB once `gitStorage` is `"indexeddb"`, and is then left out
  of localStorage.
- Git is saved immediately on change. On page hide, history IndexedDB has not
  confirmed yet is copied to `crimson_os_v1_git_pending`.
- If another tab saves the project, this tab stops saving (`staleTab`) and
  shows `SaveBanner`.
- Reset and import call `cancelWork()`: it aborts chat, stops the swarm and
  bumps `session.generation`. Async work that writes into the workspace
  after awaiting (like chat replies) must check that the generation did not
  change, so a late reply never lands in the new workspace.
- Saved data from older versions must still load: upgrade it in
  `bootPersistence` or `normalizeGit`, never assume the current shape.

**Prompts**
- The system prompt stays under `PROMPT_BUDGET`, and the open file keeps at
  least `FILE_FLOOR` characters. Cuts are marked, never silent.

## Style

- TypeScript strict. Keep logic pure and testable (`git.ts`, `prompt.ts`,
  `names.ts`) and keep the store thin. A new store area becomes a slice like
  `store-git.ts`: `(get, set) => Pick<OsState, ...>`.
- Comments say why, not what. Messages shown to the user are plain English,
  name the file or branch involved, and say what was or wasn't changed.
- Terminal output lines start with `[ERROR]`, `[INFO]`, `[SUCCESS]` or
  `[WARN]`.
- Commit messages: a short subject, then a body listing what changed and
  why. Scan the staged diff for secrets before committing.
